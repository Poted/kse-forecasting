## Jak uruchomić
```bash
uv run kse-data pse                  # 4 raporty PSE, od początku danych do dziś (plan i RCE: do jutra)
uv run kse-data weather              # pogoda od 14.06.2024 do dziś
uv run kse-data report --out docs/kompletnosc_danych.md
```
Opcje: `--start`, `--end` (RRRR-MM-DD), `--report <nazwa>` (można powtórzyć), `--data-dir` (domyślnie `data/`).
Pełne pobranie trwa ok. 3 minuty (PSE ok. 120 zapytań, pogoda 30 zapytań).

## Jak działa
**PSE.** Zapytanie `GET /api/<raport>?$filter=business_date ge 'od' and business_date le 'do'&$first=20000`. Odpowiedź ma `value` (rekordy) i — jeśli są kolejne strony — `nextLink` z gotowym adresem następnej strony (parametr `$after`). Klient pobiera strony do braku `nextLink`. Pobieranie w kawałkach miesięcznych (miesiąc ≈ 3000 kwadransów, czyli jedna strona).

Pierwsze doby: `his-wlk-cal`, `pdgopkd`, `rce-pln` — 14.06.2024; `poze-redoze` — 27.09.2024. Domyślny koniec: dziś; dla `pdgopkd` i `rce-pln` jutro, bo są publikowane na dobę następną (RCE ok. 14:00, plan ok. 16:00 dnia D).

**Open-Meteo.** `previous-runs-api.open-meteo.com/v1/forecast`, zmienne `shortwave_radiation`, `cloud_cover`, `temperature_2m`, `wind_speed_100m` z przyrostkiem `_previous_day1` (prognoza wydana dobę wcześniej), `timezone=GMT`. Wiele punktów w jednym zapytaniu (współrzędne po przecinku) → odpowiedź jest listą. Model: domyślny Open-Meteo (`best_match`). `time_utc` to znacznik godziny zwracany przez API (UTC). Wartości zapisane osobno dla każdego punktu; uśrednianie dla kraju (decyzja 08.11) — przy budowie cech (P2.5).

**Zapis.** `data/raw/pse/<raport>/<RRRR-MM>.parquet`, `data/raw/openmeteo/<RRRR-MM>.parquet` (poza gitem). Zapis kawałka usuwa z pliku wiersze z pobranych dób i wstawia nowe — ponowne pobranie nadpisuje korekty PSE, pozostałe doby zostają. Zapis przez plik tymczasowy i `replace` (przerwany zapis nie psuje pliku). Kolumny jak w API; `dtime_utc` i `publication_ts_utc` jako `datetime64[UTC]`.

**Raport kompletności.** PSE: dla każdej doby liczba kwadransów vs oczekiwana (92/96/100 wg zmiany czasu w Europe/Warsaw), brakujące doby, duplikaty `dtime_utc`, znaczniki poza siatką 15 min, udział wartości pustych w kolumnach. Pogoda: brakujące godziny (24 na dobę UTC) i puste wartości dla każdego punktu.

## Decyzje techniczne
| Decyzja | Powód |
|---|---|
| Pliki miesięczne | jedno zapytanie PSE na miesiąc; łatwe ponowne pobranie okresu z korektami |
| Zastępowanie dób zamiast dopisywania | PSE koryguje dane wstecz (pułapka 4) |
| `dtime_utc` parsowane z `format="mixed"` | `poze-redoze` podaje `dtime_utc` bez sekund (`2026-06-14 22:15`), pozostałe raporty z sekundami |
| Zapis surowy bez usuwania kolumn | wybór pól i czyszczenie w P2.3; puste kolumny widoczne w raporcie |
| Pogoda per punkt, bez uśredniania | uśrednianie (i ewentualne wagi wg mocy PV) to decyzja na poziomie cech |
| Ponawianie w `common/http.py` (własna pętla) | testowalne bez sieci (wstrzykiwana funkcja `sleep`) |

Obserwacje:
- Doby zmiany czasu mają poprawną liczbę kwadransów (92 i 100) we wszystkich raportach.
- `his-wlk-cal`: kolumny `jga`, `jgo`, `jgz1`, `jgz3` w 100% puste; `jgz2` 77%, `jgw2` 63%, `jgm2` 58% — zgodnie z pułapką 6.
- `his-wlk-cal` zawiera także bieżącą dobę (08.11) z danymi do bieżącego kwadransu; pozostałe 30 kwadransów tej doby mają wartości puste (`publication_ts_utc` 2026-11-08 16:07). Tabela dostępności w `00_fundament.md` mówi o wykonaniu za D−1 — pytanie w `docs/STAN.md`.
- `pdgopkd`: puste kolumny `gen_jga`, `gen_jgo`, `capacity_jga`, `capacity_jgo`, `gen_jgz_zak_1`, `capacity_jgz_zak_1` (100%); pola używane w projekcie (`gen_fv`, `gen_wi`, `kse_pow_dem`) bez braków.
- `poze-redoze`: wartości puste oznaczają brak redysponowania (wg `01_dane.md`); `pv_red_balance` niepuste w 13% kwadransów.
- `rce-pln`: bez pustych wartości.
- Open-Meteo: kompletne dla całego okresu, wszystkich punktów i zmiennych (w `01_dane.md` było „do sprawdzenia”).
- Ponowienia przy pobieraniu: jedno HTTP 500 z PSE (`pdgopkd`), jedno zerwane połączenie z Open-Meteo — obsłużone przez ponawianie.

## Ograniczenia
- Dane PSE w wersji z dnia pobrania (po korektach), nie w wersji dostępnej w chwili prognozy (pułapka 4).
- Open-Meteo `_previous_day1`: prognoza wydana dobę wcześniej względem godziny docelowej. Dokładny moment przebiegu modelu względem 12:00 dnia D nie był sprawdzany.

## Jak sprawdzić samodzielnie
Po `uv sync` (baza niepotrzebna w tym etapie):

1. `uv run pytest tests/test_pse.py tests/test_openmeteo.py tests/test_http.py -v` → wszystkie testy `PASSED`, bez dostępu do sieci (zapisane odpowiedzi w `tests/fixtures/`).
2. `uv run kse-data pse --report his-wlk-cal --start 2025-10-26 --end 2025-10-26` → w logu `his-wlk-cal 2025-10-26–2025-10-26: pobrano 100, …` (doba zmiany czasu: 100 kwadransów).
3. `uv run kse-data pse && uv run kse-data weather` → ok. 3 minuty, linie `pobrano N, w pliku M` dla każdego miesiąca; pliki w `data/raw/pse/` i `data/raw/openmeteo/`.
4. `uv run kse-data report` → tabela PSE z zerami w kolumnach „Brakujące doby”, „Doby z inną liczbą kwadransów”, „Duplikaty”; w części pogody 0 brakujących godzin dla 8 punktów.
