## Jak uruchomić
**Docker (baza + dashboard):**
```bash
cp .env.example .env          # jeśli brak
docker compose up -d          # db + app; dashboard: http://localhost:8501
```
Polecenia w kontenerze, np. pierwsze pobranie danych i walidacja:
```bash
docker compose exec app uv run --no-sync kse-data pse
docker compose exec app uv run --no-sync kse-data weather
docker compose exec app uv run --no-sync kse-data load
docker compose exec app uv run --no-sync kse-p2 backtest
```
**Lokalnie (bez kontenera aplikacji):**
```bash
docker compose up -d db
uv run kse-p2 forecast        # prognoza na jutro (ok. 40 s)
uv run kse-app                # dashboard: http://localhost:8501
```

## Ograniczenia
- Budowanie obrazu w środowisku Claude Code: sieć sesji nie dopuszcza `deb.debian.org`, więc krok `apt-get install libgomp1` nie mógł być wykonany. Obraz zbudowano wariantem testowym (poza repozytorium), w którym `libgomp.so.1` skopiowano z systemu hosta; reszta `Dockerfile` bez zmian. Przy zwykłym dostępie do internetu `docker compose up -d --build` buduje obraz z `Dockerfile`. `libgomp1` jest wymagane — bez niego import LightGBM kończy się błędem (sprawdzone).
- Przycisk w dashboardzie w kontenerze pobiera dane z API PSE i Open-Meteo — wymaga dostępu kontenera do internetu.
- Warunki korzystania z danych PSE nie zostały sprawdzone (pytanie w `docs/STAN.md`); w aplikacji podane jest źródło.
